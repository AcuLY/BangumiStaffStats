## Identity and set algebra

The request contains 2–10 unique people. Each has an ordered-unique non-empty
list of opaque query PositionKeys; total identities are at most 20. Every
identity belongs to the effective query and really matches its person.

For each participant, identity results are unioned on raw Subject IDs. The
common set is the intersection across participant unions. Group matrix cells
are independent pairwise intersections of the same unions, not projections of
the all-person common set. Only after these sets are fixed may mergeSeries
aggregate them. Sharing only a series while participating in different raw
works never counts as cooperation.

## Complete core and projection

The core contains ordered participant identities/metrics, summary, tags,
ratings datasets, personal preference evidence, optional upper-triangle matrix,
and complete common work items with exact participant contributions. Subject
and series items reuse the accepted person-detail identity/contribution
semantics. Series contributions carry matched workCount; Subject contributions
omit the constant one.

View fields only search/sort/page the common works. They do not alter
participants, summary, tags, ratings, preference, or matrix. Personal defaults
to personalScore; global defaults to globalScore. Missing metrics remain null
and missing sort values remain last. The expensive cache key contains operation,
dataVersion, queryDigest, canonical ordered participant input digest, and
personal collectionDigest, but excludes view.

## Empty and scope behavior

Two participants return `kind:"pair"` and omit matrix. Three through ten return
`kind:"group"` and the complete upper triangle in participant order. No common
works is a valid 200 response with zero common count, empty items/tags/datasets,
normal participant metrics/matrix, and personal zero-evidence preference.
Global structurally omits all personal fields and collection metadata.

## Wire and verification

Generation selects only `/co-star` and transitive components, uses fixed
capability-owned metadata, emits a deterministic projection hash, and proves
unrelated authority changes cannot affect generated bytes. Acceptance covers
limits/duplicates, opaque identities, staffset/cast provenance, pair/group,
raw intersection before series, matrix order, empty success, personal/global
omission, sorting/pagination, cache ownership, strict handler/error/Retry-After,
race, drift, and full backend checks.
