## Context

Backend and frontend Query generators already select the shared Query surface
from the repository OpenAPI before generation. The Query golden verifier
predates that split: it copies the complete authority and then admits only
`contracts/schemas/query/**`. Once independent endpoint components were added,
the copied document necessarily referenced files outside that closed set.

## Decisions

### Use one explicit owned projection

The verifier SHALL construct a fresh object from the shared authority with:

- accepted `openapi`, `jsonSchemaDialect`, `info`, and `servers` metadata;
- the accepted fixed Query description;
- `paths: {}`;
- exactly the manifest's 17 Query component schemas; and
- exactly the nine accepted shared error responses.

It SHALL reject missing owned members. It SHALL neither traverse nor copy any
unselected path, header, response, or external endpoint schema.

### Bind canonical projection evidence

Authority evidence SHALL describe the canonical Query projection rather than
the full shared document. Both disposable codegen trees SHALL contain identical
bytes of that projection plus the seven sanitized Query schemas. The verifier
SHALL prove that adding a synthetic unrelated path/component cannot change the
projection digest, while changing an owned component does.

### Keep implementations independently comparable

The golden verifier may define its own small projection helper, but its output
and generated Query bytes SHALL agree with the existing backend and frontend
Query generation gates. No shared generator is edited in this correction.

## Risks / Trade-offs

- An explicit inventory requires review when Query intentionally gains a
  component; that is the desired fail-closed behavior.
- Comparing generated bytes catches divergence among the three projection
  implementations without creating a new shared mutable helper.

## Migration Plan

1. Implement and verify the Query-only projection in disposable owned state.
2. Update only affected closed manifest evidence and verifier identity.
3. Run all Query, backend Query-wire, and frontend Query-wire gates twice where
   determinism is material, then remove exact generated roots.
4. Main agent audits, syncs, archives, commits, and rebuilds product artifacts.
