## Why

The full Query verifier still audits and copies the complete shared OpenAPI
document while admitting only the seven Query schema files. The accepted
rankings, candidates, person-detail, partners, and co-star operations add their
own external schemas, so the verifier now rejects the first unrelated reference
before it can prove the Query contract. Query generation already defines a
closed query-only projection; the golden verifier must use that same ownership
boundary.

## What Changes

- Build a deterministic Query OpenAPI projection containing no paths, exactly
  the 17 accepted Query component schemas, and exactly the nine accepted shared
  error responses.
- Normalize the projection description to the accepted Query description and
  audit/copy that projection instead of the complete evolving authority.
- Bind the manifest authority and generated-projection evidence to the exact
  canonical Query projection while proving unrelated paths/components do not
  change it.
- Rebind only the Query verifier self identity and affected closed projection
  evidence.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `contracts-query-wire`: make Query golden authority admission match the
  accepted capability-owned projection.

| Stop conditions | Stop if the accepted Query component/response inventory is ambiguous, generated Query bytes change, a protected path must change, or exact cleanup fails. |
