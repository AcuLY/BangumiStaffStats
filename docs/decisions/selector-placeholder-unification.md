- `OUT_OF_SCOPE`：审计中提到，但用户确认不属于本轮 selector 与 placeholder 核对范围。
- `NEEDS_DECISION`：仍需用户确认，不能进入实现。

## 已确认决策

### DR-UI-COPY-001 · 工作台模式名称

2026-07-20，用户确认统一使用 `共演分析`。

- 顶部模式 Tab、页面标题、结果标题、空状态、辅助说明和无障碍名称统一使用 `共演分析`。
- `DESIGN.md`、页面 meta 等面向用户或设计规范的名称同步统一。
- TypeScript 内部值、CSS 语义类名和其他技术标识中的 `co-star` 不因本项改名。

### DR-UI-COPY-002 · 评分术语

2026-07-20，用户确认按数值含义区分：

- 需要直接区分两种数据来源的单部作品数值：`我的评分 / 全站评分`。
- 需要直接区分两种数据来源的多部作品平均值：`我的均分 / 全站均分`。
- 加权计算结果：`综合分`。
- 现有 `我的分数 / 全站分数` 应按其语义替换，不再作为另一套同义名称保留。

2026-07-21，用户进一步确认：“我的”只应出现在需要和“全站”做区分的场景；随后确认同类限定词采用同一上下文规则。

- 同一控件、指标组、作品行或说明中同时存在个人与全站口径时，保留带来源的完整名称。
- 当前查询模式已经唯一确定任一评分来源时，只写 `评分 / 均分`；人物排行表头、排序项、行级无障碍摘要以及全站单来源图表均采用这一规则。
- 直接比较两种来源时统一写 `我的评分 / 全站评分`，不再混用 `个人评分`；没有个人同名对应项的全站评分规模统一简写为 `评分人数`。
- 没有全站同名对应项的个人专属概念不加“我的”，统一使用 `收藏作品 / 最高评分 / 最低评分 / 收藏标签 / 相对偏好`。

### DR-UI-COPY-003 · 全站模式下的个人专属控件

#### 确认结论

2026-07-20，用户确认采用“全部隐藏”方案：

- 全站模式不渲染个人专属的查询、筛选、排序和图表切换选项。
- 评分来源只剩固定的 `全站评分` 时，整个来源切换控件消失，而不是留下 disabled 的 `我的评分`。
- `相对偏好` 等个人专属分析区块整体消失，不保留只用于解释不可用原因的空区块。
- 凡是表示用户个人评分数量的 `已评分 / 已评作品`，无论位于详情指标还是其他界面，均在全站模式隐藏。
- 全站口径下“具有有效全站评分的作品数”不是个人数据；若以后需要展示，应作为独立的全站指标另行定义，不能沿用个人 `已评分` 的含义。本项不登记该未来功能。
- 数据来源差异如需说明，集中放在数据来源切换附近，不在每个下游位置重复。

#### 实施前现状

当前实现同时存在隐藏、disabled 和“保留整个空区块并解释”三种策略：

- 查询编辑器会隐藏 UID、收藏类型、收藏时间、我的评分范围和个人－全站评分差。
- 候选人物排序会隐藏 `我的均分`，作品排序会隐藏 `我的评分`，排行排序会隐藏 `相对偏好`。
- 两种评分分布图仍显示 disabled 的 `我的评分` 数据来源；全站模式下实际固定使用 `全站评分`。
- 单人物合作排序仍显示 disabled 的 `偏好（仅个人收藏）`。
- 人物详情和多人分析的 `相对偏好` 仍保留整个区块，但只显示“仅在个人收藏模式计算”的说明。

全站排行目前仍出现 `我的均分` 和依赖个人数据的 `综合分`。这是指标定义冲突，不是单纯的显示策略，留作独立决策。

#### 问题

- 同一种“当前模式不可用”语义没有一致反馈：用户无法预期某项会消失、变灰，还是留下一个空区块。
- disabled 项可能被理解为权限不足、数据未加载或暂时不可操作，而不一定能表达“切换到个人收藏模式才存在”。
- 只剩 `全站评分` 一个有效值时，继续显示二选一切换器会形成无效操作和额外视觉噪声。
- 保留无数据的个人偏好区块会占用高密度工作台的浏览空间，并在多个位置重复解释同一模式差异。

数据来源切换器已经提供进入个人收藏模式的明确入口，因此本项不再保留 disabled 项或说明性空区块来维持功能可发现性。

### DR-UI-METRIC-001 · 全站人物排行指标

#### 确认结论

2026-07-20，用户确认：

- 全站人物排行不显示 `相对偏好`，对应排序选项和整列一并隐藏。
- 全站模式显示 `作品数 / 均分 / 综合分`；数据仍取全站口径，只因当前模式已唯一确定来源而省略可见限定词。
- 全站 `综合分` 使用与个人模式相同的公式结构，但输入改为全站评分口径。
- 综合分公式中的 `n` 统一使用有效评分作品数；评分为 0 或缺少有效评分的作品不增加收缩权重。
- 用户预期现有后端已经按此实现；代码验证确认个人与全站模式共用后端 `CalcOverall`。
- `组合评分对比` 跟随当前查询模式：个人模式读取个人均分，全站模式读取全站均分，标题保持通用名称。

#### 后端代码验证与修复

- `backend/internal/core/statistic/statistic.go` 在个人与全站路径汇合后，统一调用 `subject.CalcAverage` 和 `subject.CalcOverall`。
- 全站路径读取数据库中的全站 `Subject.Rate`；个人路径在 `subject.Build` 中先把同一字段替换为用户收藏评分，再进入相同统计函数。
- `CalcOverall` 不读取每部作品的 `ratingCount`，因此不存在按全站评分人数加权。
- 修复前公式为 `n / (n + 5) * average + 5 / (n + 5) * 5`，但 `n = len(subjs)`，错误包含评分为 0 的作品。
- `CalcAverage` 会忽略评分为 0 的作品。因此后端的分子均分只统计有效评分，但收缩权重中的 `n` 包含评分为 0 的作品。

这里与 Vue 原型及 `DESIGN.md` 存在一处口径差异：原型使用 `ratedSubjectCount`，即只用有效评分作品数作为 `n`。用户确认后端的 `n = len(subjs)` 属于遗留问题；应由后端向有效评分作品数口径对齐，而不是让原型和设计文档回退到全部作品数。

2026-07-21 已修复：`CalcAverage` 与 `CalcOverall` 共用“截断后均分 + 有效评分数”计算，`CalcOverall` 使用 `Rate != 0` 的有效条目数作为 `n`。均分仍先向下截断两位，综合分仍最终四舍五入两位；未引入 `ratingCount` 加权、API 字段或新的可见“已评数量”指标。

#### 实施前现状

当前全站人物排行仍显示四列 `作品 / 均分 / 综合 / 偏好`：

- `均分` 实际读取个人收藏中的 `userAverage`。
- `综合分` 实际以个人收藏中的已评分作品数和 `userAverage` 计算。
- `偏好` 在全站模式没有值，只显示 `—`。
- 已经计算出的 `globalAverage` 没有用于排行列表的均分列和综合分。

这会让“全站数据”模式混入个人收藏口径。实施时必须同时修正显示列、排序值和综合分输入，不能只改标签。

### DR-UI-COPY-004 · 搜索 Placeholder 标点

#### 确认结论

2026-07-20，用户确认：

- 所有搜索类 placeholder 去掉末尾省略号。
- 不能只机械删除标点；应同步统一并缩短 placeholder 内容。
- 文案必须适应工具栏在窄视口下的弹性收缩，避免关键对象名称被裁切。
- 本项只修改可见 placeholder；不新增或修改 `aria-label`、tooltip、帮助文案、布局、响应式 CSS 或其他适配。

#### 实施前现状

当前搜索类 placeholder 的末尾标点不一致：

- 无省略号：`搜索人物或 ID`、`搜索合作作品`。
- 有省略号：`筛选当前结果…`、`搜索中日文标题、人物或角色名…`、`搜索中日文标题或角色名…`、`搜索角色双语名或来源作品…`。

现有作品和角色搜索 placeholder 最长达到十余个汉字，而搜索输入会和排序 selector、方向按钮共享弹性工具栏宽度，窄视口下必然优先裁切这类说明性文字。

### DR-UI-COPY-005 · 搜索 Placeholder 词表

#### 确认结论

2026-07-20，用户确认只缩减 placeholder，不做其他任何适配：

### DR-UI-COPY-006 · 月份与年代 Placeholder

2026-07-21，用户确认两个手动月份选择器继续使用：

- `最早时间`
- `最晚时间`

`指定年代` 是与 `近 1 年 / 近 3 年 / 近 5 年` 并列的快捷范围 selector。选项从当前年代向前生成到 1950 年代；例如选择 `1990 年代` 会把起止范围一次性设为 `1990-01` 至 `1999-12`。只有当前起止值恰好覆盖完整十年时，selector 才显示对应年代，否则显示 placeholder `指定年代`。

2026-07-21，用户确认年代快捷 selector 的 placeholder 改为 `选择年代`。

### DR-UI-COPY-009 · 标签输入 Placeholder

正向标签和反向标签输入当前都使用 `输入标签后回车`。

审计曾建议改为 `输入标签并按 Enter`，目的是把操作关系写完整，并使用键盘实际键名；但新文案更长。

2026-07-21，用户确认 `输入标签后回车` 保持不变，并要求在实际窄视口下验证该 placeholder 是否被裁切。该验证只检查当前渲染结果，不授权修改布局或其他适配。

同日完成当前 Vue 工作台的运行态验证：

- 在 `320×800` 和 `390×844` 视口中，正/反向标签输入框宽度均为 `144px`、字体为 `12px`，placeholder 可见内容完整。
- 在小屏断点两侧，`779×900` 时输入框为 `144px / 12px`，`780×900` 时为 `140px / 14px`，placeholder 均未裁切。
- 桌面 `1280×720` 下输入框为 `140px / 14px`，placeholder 未裁切。
- 验证过程中未发现页面 `warn` 或 `error` 控制台日志。

结论：保留 `输入标签后回车`，不需要为该项增加布局或响应式适配。

### DR-UI-COPY-010 · 职位选择 Placeholder

查询编辑器第二阶段的职位多选框根据工作台模式显示不同文案：

- 人物排行模式：`选择排行职位…`
- 共演分析模式：`选择参与职位…`

2026-07-21，用户确认分别改为 `选择排行职位` 和 `选择参与职位`。本项只删除末尾省略号，不调整当前 Vue 实现中的选择器位置、含义、选项或多选交互。

`DESIGN.md` 原有的共演职位目标形态仍是“单选 selector + 添加 + 有序列表”；当前 Vue 实现仍为多选 selector。两者的既有差异不属于本轮 placeholder 修改，本轮既不把目标规范改写为多选，也不声称已完成该交互迁移。

### DR-UI-COPY-011 · 追加身份 Selector

### DR-UI-COPY-012 · 分页跳转 Placeholder

结果区分页底部的快速跳转控件当前显示 `跳至` 和一个无 placeholder 的页码输入框。原审计建议为输入框补充 `页码`。

### DR-UI-SCOPE-001 · 已选人物空状态

### DR-UI-COPY-013 · 分页 Selector

当前人物分页文案和档位不一致：

- 人物排行显示 `每页 5/10/20 人`。
- 候选人物显示 `每页 5/10/20/50 人`。

用户随后明确把档位规则扩展到作品和角色分页。因此最终规则为：人物、作品和角色的 page-size selector 均只保留 `5 / 10 / 20`，全站删除 `50` 档；各 selector 继续使用对应单位 `人 / 部 / 个角色`。

### DR-UI-SELECTOR-001 · 排行职位选择规则

当前人物排行的职位 selector 支持多选，提示为“可多选；仅保留同时具备全部所选职位的人物”；但 `DESIGN.md` 仍把排行职位描述为单选。

- 入选人物在各所选职位下的参与作品取并集，并按作品 ID 去重后计算指标。
- 查询状态继续使用职位数组；同步修正 `DESIGN.md` 中“当前 UI 只允许一个职位”等单选描述。

### DR-UI-SELECTOR-002 · 收藏日期排序

人物详情、单人物合作作品和多人共同作品的排序 selector 包含 `收藏日期`。当前比较器实际使用 `collection.updatedAt ?? subject.date`，会在收藏日期缺失时回退到作品日期，使同一个排序维度混用两种日期语义。

2026-07-21，用户确认：

- selector 名称继续使用 `收藏日期`。
- 选择该排序维度时，只使用收藏记录的日期。
- 缺少收藏日期的条目直接从该排序结果中排除，不使用作品日期替代。

### DR-UI-COPY-014 · 空 Selector 默认 Placeholder

未显式提供 placeholder 的 `NSelect` 在值为空时会继承框架默认文案 `请选择`；多数此类 selector 已有默认值，因此该文案通常不会出现。

2026-07-21，用户确认保持现状：不为这些 selector 逐一增加自定义 placeholder，空值时继续显示 `请选择`。

### DR-UI-COPY-015 · Selector 空结果文案

`NSelect` 下拉菜单在没有任何选项或搜索不到匹配项时，会继承框架默认空结果文案 `无数据`。该文案属于 selector 内部反馈，不是页面级空状态。

2026-07-21，用户确认保持 `无数据` 不变，不增加场景化替代文案。

### DR-UI-COPY-016 · 标签触发按钮

正向、反向标签控件尚未进入输入状态时，使用真实加号图标和 `添加标签` 按钮触发动态输入框；点击后出现 placeholder `输入标签后回车`。

2026-07-21，用户确认 `添加标签` 保持不变。旧原型中的 `＋ 添加身份…` 已随追加身份 selector 一并移除，因此两者不再构成语法不一致问题。
