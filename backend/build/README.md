# Backend development artifact

This directory builds the development-only Backend artifact set. It does not
publish, release, deploy, activate an Archive, or choose production topology.

The build emits:

- a normalized `linux/<arch>` API binary bundle;
- a normalized local OCI image archive built from literal, non-overridable
  digest-pinned bases;
- a complete sorted SHA-256 inventory;
- a deterministic SPDX 2.3 JSON SBOM;
- a Contracts-schema Backend component statement.

Generated bytes and fresh caches remain below ignored `build/.tmp/`. The final
local set is addressed by the SHA-256 digest of all of its canonical files and
an existing address is never overwritten with different bytes.

The production `build.sh` and `check.sh` entrypoints first attest the canonical
repository top-level, committed `HEAD` revision/tree/epoch, matching index and
tracked worktree, and absence of untracked non-ignored paths. Caller-provided
`SOURCE_REVISION`, `SOURCE_TREE`, or `SOURCE_DATE_EPOCH` values may only exactly
restate those derived values. Source drift fails before `build/.tmp/`, cache,
or output creation. The build then materializes the complete candidate tree
from raw, filter-free Git blobs and uses only that isolated snapshot for
contract digests, helper compilation, Dockerfile reads, Docker context, and
offline Contracts validation. Ignored live-worktree files therefore never
enter the build context. An untracked nested `.gitignore` is tolerated only
when a tracked strict-parent `.gitignore` already ignores its containing
directory; it cannot create a new ignored source subtree.

Use the pinned Go toolchain declared by `go.mod`:

```sh
cd backend
./build/test.sh
artifact_root="$(./build/build.sh --output-root build/.tmp/manual)"
./build/smoke.sh --artifact-root "$artifact_root"
./build/check.sh
```

`build.sh` accepts `--target-arch amd64` or `--target-arch arm64`; byte
reproducibility is defined only for identical source, declared compatibility
inputs, target platform, pinned toolchain, and pinned base-image digests.
Build and smoke require a running Docker daemon plus Node 24.18.0 for the
Contracts-owned offline validator. Smoke disables the API network, mounts only
a disposable read-only accepted Archive, and probes loopback from a separate
container sharing that network namespace.
